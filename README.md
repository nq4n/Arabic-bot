أداة للمساعدة على الكتابة

## تسجيل دخول الطلاب باسم المستخدم فقط

الطلاب يدخلون المنصّة باسم المستخدم فقط (مثال: `s123456`) دون كلمة مرور.
المعلمون والمسؤولون ما زالوا يدخلون بالبريد/اسم المستخدم مع كلمة المرور.

**كيف يعمل:**

1. في أعلى بطاقة الدخول مفتاح لاختيار الفئة: **طالب** (افتراضياً) أو
   **معلم**. في وضع الطالب يظهر حقل اسم المستخدم فقط، وفي وضع المعلم
   يظهر معه حقل كلمة المرور.
2. صفحة الدخول ترسل اسم المستخدم إلى وظيفة `student-login`.
3. الوظيفة (بصلاحية `service_role`) تتحقق من الحساب، وإذا كانت صلاحيته
   `student` تنشئ رمز دخول لمرة واحدة (`magiclink`) وتعيد `hashed_token`.
4. العميل يستدعي `supabase.auth.verifyOtp({ token_hash, type: "magiclink" })`
   فيحصل على جلسة Supabase حقيقية، وتبقى سياسات RLS والصلاحيات كما هي.
5. إذا دخل معلم من وضع الطالب تعيد الوظيفة `requiresPassword: true`،
   فينتقل المفتاح تلقائياً إلى **معلم** ويظهر حقل كلمة المرور. وإذا
   تعذّر الوصول إلى الوظيفة يظهر حقل كلمة المرور كخطة بديلة.

**عند إنشاء الطلاب:** لا حاجة لعمود/حقل كلمة المرور؛ تُولَّد كلمة مرور
عشوائية لا تُعرض ولا تُستخدم، ولا يُطلب من الطالب تغييرها.

**النشر:**

```bash
supabase functions deploy student-login
supabase db push   # لتطبيق 202611020001_student_passwordless_login.sql
```

**ملاحظة أمنية:** مع إلغاء كلمة المرور، اسم المستخدم وحده يكفي للدخول
إلى حساب الطالب، فمن يعرف اسم المستخدم يستطيع الدخول باسم صاحبه. إن
أردت حماية أقوى لاحقاً، أضف رمزاً قصيراً للصف أو رقماً سرياً للطالب
إلى جانب اسم المستخدم.
