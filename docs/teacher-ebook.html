إدارة المستخدمين

  • إضافة مستخدم واحد عبر نموذج يدوي.
  • استيراد مجموعة مستخدمين عبر CSV.
  • المعلم يضيف طلابًا فقط، بينما المشرف يستطيع إضافة كل الأدوار.
  • إظهار عدد تسليمات كل مستخدم داخل الجدول.
  • الحذف الفردي أو الجماعي مع نافذة تأكيد.
  • المشرف فقط يغيّر الدور أو يفعّل إجبار تغيير كلمة المرور.

الفصل 3

أنواع الإتاحة

المعلم يتحكم في ما يراه الطالب على مستوى كل درس، وليس فقط في فتح الدرس أو إغلاقه بالكامل.

  • lesson: السماح بالدخول إلى الدرس من صفحة الموضوعات.
  • video: إظهار قسم الفيديو داخل صفحة الدرس.
  • review: السماح بالانتقال إلى صفحة مراجعة الدرس.
  • evaluation: السماح بالدخول إلى الكتابة والتقييم.
  • activity: تشغيل زر النشاط وصفحة التطبيق العملي.

الأثر على الطالب

  • إذا أُغلق lesson يتعطل زر "عرض الدرس" من الصفحة الأولى.
  • إذا أُغلق review يتعطل زر "الانتقال إلى مراجعة الدرس".
  • إذا أُغلق evaluation تظهر رسالة "قسم الكتابة والتقييم غير متاح حاليًا".
  • إذا أُغلق activity يتعطل زر النشاط وتُغلق صفحة التطبيق نفسها.
يمكن فتح المراجعة وإبقاء التقييم مغلقًا، أو فتح الدرس وإخفاء النشاط. هذه المفاتيح مستقلة.

الفصل 5

التسليمات والتقييم والدردشة

  • صفحة /submissions بعنوان كل التسليمات وتحتوي على فلتر الدرس:.
  • كل بطاقة تسليم تعرض: اسم الطالب، اسم الموضوع، تاريخ التسليم، تقييم الذكاء الاصطناعي، وتقييم المعلم.
  • صفحة /submission/:id تعرض نص الطالب ثم تقييم الذكاء الاصطناعي ثم تقييم المعلم.
  • لا يمكن حفظ تقييم المعلم قبل اختيار مستوى لكل معيار rubric.
  • مركز الدردشة يربط المعلم بطلبته، ويتيح تعطيل الدردشة العامة على مستوى الطلاب عبر الدردشة للطلاب.
الطالب يرى رسالة واضحة إذا كانت الدردشة غير متاحة. أما المعلم أو المشرف فيستطيعان تبديل هذه الحالة من المركز نفسه.

كيف تُقرأ الواجهة

ما الذي يراه المعلم في كل شاشة؟

1. لوحة الإدارة

تجمع إعدادات الإتاحة، إضافة المستخدمين، وقراءة جدول الحسابات في صفحة واحدة.

2. تقارير الأنشطة

تُستخدم للمشاهدة السريعة: من أنجز؟ من أرسل؟ ومن يحتاج مراجعة أو إعادة نشاط تعاوني.

3. صفحة التسليمات

هي نقطة الانتقال من القراءة العامة إلى مراجعة كل نص بالتفصيل داخل /submission/:id.

4. الدردشة والملف

الدردشة للتدخل السريع، والملف الشخصي لقراءة حالة الحساب ومعلوماته الأساسية.

هذا الفصل هو الأقرب بصريًا إلى شكل الصفحات الفعلية الموجودة في المشروع الآن.

الفصل 7

كل صفحات المعلم ومسار استخدامها

هذا الفصل يجمع كل الصفحة التي يمر بها المعلم أو المشرف داخل المشروع الحالي، مع وظيفة كل صفحة ولماذا ينتقل إليها.

/login

نقطة الدخول الأولى للحسابات قبل الوصول إلى شريط التنقل الخاص بالمعلم.

/teacher

إدارة المستخدمين، الإتاحة، CSV، إنشاء الحسابات، وحذفها أو تعديل أدوارها.

/activity-submissions

مراقبة النشاطات الفردية والتعاونية ولوحة الصدارة وسجل التتبع.

/submissions

قراءة قائمة الكتابات كاملة ثم تصفيتها حسب الدرس أو الطالب.

/submission/:id

فحص نص طالب واحد، قراءة تقييم الذكاء الاصطناعي، ثم وضع تقييم المعلم.

/chats

محادثات المعلم مع الطلاب، وتعطيل أو تفعيل الدردشة العامة للطلاب.

/profile

قراءة البريد، الدور، وبيانات الحساب التي تظهر في القائمة المنسدلة.

استخدام يومي

كيف يتحرك المعلم خلال يوم العمل؟

1. بداية اليوم

يفتح /teacher ليراجع الإتاحة الحالية، أو يضيف طالبًا جديدًا، أو يرفع دفعة CSV كاملة.

2. متابعة التنفيذ

ينتقل إلى /activity-submissions ليرى من أرسل النشاط، ومن أنهى نشاطًا تعاونيًا، ومن يحتاج تدخلًا.

3. مراجعة الكتابة

يفتح /submissions ثم يدخل إلى /submission/:id لمراجعة نص معين وحفظ تقييمه.

4. التواصل والإغلاق

يستخدم /chats للرد السريع، ثم /profile لمراجعة حالته أو الخروج من النظام.

بهذا يكون الكتاب قد غطى كل صفحة معلم ظاهرة في المشروع الحالي، من الدخول حتى التقييم والتواصل.
